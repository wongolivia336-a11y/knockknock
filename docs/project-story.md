# KNOCK KNOCK：看不见它，但它会回应

## 作品命题

KNOCK KNOCK 是一项关于陪伴关系的课程设计。它从一个简单的问题出发：如果我们不知道陪伴对象是什么样子，照料和回应本身能不能让关系发生？

我们没有把答案藏在盒子里。盒子保持封闭，也没有被确认的动物身份。用户敲击、等待、触摸或倾听，盒子用光、声音、停顿与细微动作作出回应。人再根据这些片刻，慢慢判断它的节奏、习惯和性格。

作品想验证的是“我感到它注意到了我”，而不是“我猜中了它是什么”。

## 概念如何走到今天

早期概念汇报的 16 页内容记录了项目起点。那一阶段借用了薛定谔的猫、灯笼式外壳、宠物行为隐喻和 Stack-chan 等视觉假设，讨论“看不见外形时，陪伴如何发生”。汇报文件保留在课程资料文件夹中，没有上传到公开仓库。

后续原型逐渐收敛到没有固定动物外形的一体成型方盒。我们保留早期探索中的核心问题，减少了会替用户确认身份的造型线索，并把设计重心移到人与盒子之间的动作、等待和回应上。PPT 展示的是概念起点，当前网页展示的是之后形成的交互方案；两者造型差异体现迭代过程。

结合上一轮结题反馈与原型走查，我们把后续优化集中在三件事上：让用户更容易找到并理解互动入口，让光场对触碰与等待有更清楚的回应，以及让手机端页面滚动时不误触盒子。信息架构也进一步明确：盒群岛讲的是盒子之间的关系，不是主人之间的社交网络。

## 体验叙事

### 1. 邀请

用户敲两下、轻轻碰，或停在盒子附近。动作本身很小，不要求用户完成任务，也不把互动做成输赢。

### 2. 等待

盒子不必马上回应。短暂安静是体验的一部分，等待让用户有机会留意下一次变化，也让“回应”不只是按钮按下后的机械闪烁。

### 3. 感到回应

光团朝触点靠近，形成柔和的局部焦点，再缓慢弥散；安静状态下，光场仍有轻微漂移。声音保持含蓄，不模拟可辨认的猫叫、狗叫或其他特定动物声音。

### 4. 留下线索

光的位置、停留时间、触摸、敲击与声音被整理成相处记录。记录是回看的证据，不是给盒子贴上不可更改的标签。

### 5. 暂时理解

性格档案把重复出现的行为描述成“慢热”“好奇”或“安静”等倾向。结论保持开放，下一次互动仍可能带来不同理解。

### 6. 走向盒群岛

用户可以从自己的盒子走向一座由盒子构成的群岛，听一段来访声音、留下一个回应，再回到自己的盒子。这个路径把陪伴从单个对象延伸为盒子与盒子之间的匿名、异步联系。

### 7. 回到下一次相处

来访不会结束故事。用户回到自己的盒子，带着新线索继续照料；新的动作又成为下一次回应的条件。作品因此形成循环：

```text
邀请 → 等待 → 感到回应 → 留下线索 → 暂时理解 → 盒子间传递回应 → 再次照料
```

## 四种动作怎样表达关系

| 用户动作 | 盒子的反馈 | 关系含义 |
| --- | --- | --- |
| 敲两下 | 光先收拢并短暂停顿，随后重新扩散；伴随轻柔敲击声 | 发出邀请，也给回应留出时间 |
| 等一会儿 | 光缓慢自主漂移，出现克制的细微声音 | 不催促，观察它是否会回应 |
| 轻轻碰 | 光团向触点靠近，聚焦后慢慢散开 | 接触与安抚 |
| 听听看 | 光场柔和呼吸，声音轻微出现 | 把注意力从操作转向倾听 |

六种光场预设改变颜色气质，但不会替代互动逻辑。无论选哪一种，光仍然承担回应，而不只是背景装饰。

## 网页与 App 原型如何分工

- 网页左侧的 3D 场景负责让人直接感到盒子的存在与回应。它使用 Three.js、WebGL 和 GLSL 实时生成盒体与光场。
- 网页右侧的手机尺寸界面负责承接日常照料：今天的盒子、相处记录、盒群岛和性格档案。
- 网页桌面布局把两个对象并置，手机浏览则让用户沿页面浏览场景、光场介绍和产品理念。

建议从 [在线原型](https://knockknock-theta.vercel.app/) 开始，再依次体验触碰、等待、记录和盒群岛。演示视频可在[这里播放或下载](../course-materials/knockknock-product-video.mp4)。

## 原型实现到哪里

当前网页让人体验核心交互，但没有把概念包装成已完成的硬件或在线社交服务：

- 盒体与光场在浏览器中实时渲染；页面不依赖一张静态图片伪装 3D 交互。
- 轻敲、纸面窸窣等声音由 Web Audio API 程序化生成。
- 相处状态、声音设置和收藏保存在当前浏览器的 `localStorage`。
- 盒群岛来访使用可重复体验的示例内容；尚未接入真实邻居、账号系统、跨设备同步或服务端消息。
- 当前作品是课程交互原型，不代表实体机器人已经制作或部署。

这些边界让体验可以讨论“如果盒子真的回应，人会怎样照料它”，也避免把模拟的来访误说成真实用户活动。
